# Rust 后端架构

## 入口与职责

`src-tauri/src/lib.rs` 组合协议、插件、共享状态与 commands；`lifecycle.rs` 编排启动初始化、主窗口创建、启动提示与退出清理。启动顺序见[架构总览](README.md#启动边界)。退出时等待数据库连接关闭。

| 模块 | 职责 |
| --- | --- |
| `database` / `entity` | IPC 数据边界、仓储事务、SeaORM 实体 |
| `game` | 扫描、Steam 启动解析、进程监控、会话统计、封面 |
| `install` | 安装协议、持久化任务、下载、校验、解压和导入 |
| `backup` | 数据库、封面、游戏存档备份与恢复 |
| `oauth` | 提供方授权、本地回调和凭据交换 |
| `utils` | 文件、HTTP、图片协议、日志、更新和运行环境 |

安装下载引擎位于独立 crate `src-tauri/reina-download`，由 `install/download.rs` 接入。Windows、Linux 的游戏启动与监控分别实现；当前没有 macOS 对应实现。

## 数据库边界

```text
Tauri command → database/service.rs → DTO 清洗与校验
             → database/repository/ → SeaORM entity / transaction → SQLite
```

`database/db.rs` 管理连接与 SQLite 配置。安装、备份等工作流可直接组合仓储、实体、文件系统和 HTTP。

- 游戏聚合写入在同一事务中维护 `games` 与 `game_sources`；来源的外部 ID 和元数据不能同时为空。
- 合集、会话统计等跨表不变量由仓储事务维护；安装导入将游戏写入与任务完成提交到同一事务。
- 更新 DTO 的 `Option<Option<T>>` 区分“不修改”与“显式清空”。

schema 由 `src-tauri/migration` 顺序迁移，入口统一管理迁移备份：新库不备份，已有库有待执行迁移时先备份一次。备份失败停止迁移；迁移失败保留快照并返回路径。修改 schema 时同步实体、DTO、仓储和前端类型。

## 运行环境与数据路径

`utils/runtime.rs` 在访问数据和初始化插件前固定环境，进程内不能切换。开发与正式环境由运行模式决定，与构建优化级别无关。

`reina-path` 统一路径策略：

| 环境 | 业务数据根目录 |
| --- | --- |
| 开发 | 系统 data 目录下的开发标识目录 |
| 正式标准模式 | 系统 data 目录下的正式标识目录 |
| 正式便携模式 | EXE 同级 `resources`，由 `resources/data` 目录判定 |

数据库位于 `<base>/data/reina_manager.db`。数据库备份默认在 `<base>/data/backups`，存档备份默认在 `<base>/backups`；自定义存档备份根就是实际存储目录。

少量启动设置存于插件的 `settings.json`，业务设置存于 SQLite；封面、备份和安装中间文件存于文件系统。

开发版隔离单实例、业务数据和 Tauri 插件存储，忽略便携数据，不自动复制正式版数据；导入备份不会改写其中的游戏、安装和存档路径。开发版不注册自动更新、开机启动插件，前端通过 `settingsService.isDevelopment()` 获取同一环境。

开发版与正式版共用 `reinamanager://install`。Windows、Linux 最后成功注册的版本接收系统协议链接；开发版退出不会恢复正式版关联，需要重新启动正式版。

## 用户配置路径

数据库保存路径原始表达式，实际 I/O 前通过 `reina-path::resolve_user_path` 解析。Windows 展开开头的 `%VAR%`；Linux 展开开头的 `$VAR`、`${VAR}`、`~`、`~/`。解析器只保证绝对路径，不访问文件系统；command 或 workflow 再按用途校验文件、目录或可执行文件。

程序内部生成路径，以及选择、扫描、拖拽、导入返回的一次性路径，使用实际绝对路径，不进行变量展开。运行时解析失败不能自动清空用户配置；数据库备份目录解析失败会警告并回退默认目录。

## 安装任务

任务状态与载荷持久化到 SQLite，运行时控制由 `TaskRuntimeState` 管理，进度通过 Tauri event 推送。后端负责下载、校验与解压，前端完成元数据鉴权和匹配后再调用导入 command。

- 创建任务时解析安装根目录，并在载荷中保存绝对路径快照；暂停、恢复和重试沿用该快照。
- 完成导入前再次检查配置表达式是否仍指向实际目录；不一致或无法解析时保存实际绝对路径并提示用户。
- 启动恢复由后端区分可续跑、需前端接续和需重试的任务，保留可用于重试的中间文件；状态转换规则见 [`install/persistence.rs`](../../src-tauri/src/install/persistence.rs)。

第三方安装包由 `install/archive.rs` 调用随应用打包的归档工具，工具来源与内容由 `build.rs` 校验；存档与封面备份使用 Rust 归档库。

## 封面资产

[`game/cover/assets.rs`](../../src-tauri/src/game/cover/assets.rs) 管理独立于游戏主键的 UUID 图片和资产关联。云封面随来源写入在同一事务中登记 UUID，文件按需下载；来源身份、图片地址变化或单游戏主动刷新会更换对应资产，普通批量更新复用未变化的资产。前端按资产 UUID 请求，下载只能补全仍有效的资产，不能重建已失效关联；未下载或下载失败的记录保留供后续重试。来源替换或删除在事务提交后定向清理旧文件，失败保留残留并记日志。

每款游戏最多关联一张自定义封面，图片先落盘，再提交关联，成功后清理旧文件；自定义封面保存、云封面落盘、手动清理与备份恢复共用操作锁；云下载联网阶段不持锁。

自定义封面保存与旧文件迁移共用 `game/cover/custom.rs` 的优化流程：静态图在资源预算内等比缩小到显示尺寸上限，再使用 libwebp 有损编码，透明通道无损编码；不放大小图，未缩放时仅采用更小的结果。动画、不支持安全转换的图片和优化失败的图片保留原文件。文件大小不作为上传拒绝条件，超出解码预算时流式复制；普通资料保存不重新编码已有封面。

旧自定义封面迁移不额外保留原图副本；正式图片落盘、关联提交后才删除旧位置的文件，提交前失败仍保留旧文件供重试。

单张封面迁移失败不会中断其他封面的处理；目录扫描失败保留现场，无法完成旧目录归集时跳过后续转换，均在下次启动重试。影响显示的失败会汇总为启动警告；优化回退、已可用封面的旧文件或空目录清理失败只写日志。

数据库迁移负责搬迁旧封面关联；[`utils/legacy_migration.rs`](../../src-tauri/src/utils/legacy_migration.rs) 负责可重复执行的文件迁移。保留旧文件名映射，支持配套旧封面包延后恢复；迁移成功删除旧文件，无关联的已识别旧封面直接清理。用户更换或删除封面后，旧映射失效。

自定义封面文件缺失时保留关联并展示不可用状态，不回退云封面。启动不扫描无用资产；设置中的手动清理只处理受管目录内无关联的 UUID 图片和遗留临时文件，保留待下载资产及缺文件的关联。自定义封面恢复依赖配套数据库与图片备份，云缓存可重建。

## 数据库与封面备份

数据库备份、封面备份、自动备份和数据库导入共用操作锁；数据库关闭后拒绝新的备份操作。

定时自动备份使用 SQLite 热备份；退出自动备份在关闭连接后做冷备份。同批数据库与可选自定义封面共用批次 ID，保留数量按批次计算。产物先写入同目录临时文件再发布，封面归档发布前自检；封面失败作为警告返回，数据库备份仍继续。

数据库导入由 [`backup/database.rs`](../../src-tauri/src/backup/database.rs) 负责。待导入库必须已有业务结构；零字节文件、缺少业务结构的库以及包含当前程序不支持的迁移记录的库会被拒绝。校验和旧版升级在临时副本上完成，升级后检查完整性和外键；准备失败不替换当前数据库。

关闭连接前先常规备份当前数据库和自定义封面，任一备份失败都暂停，由用户决定是否跳过失败的备份。无论常规备份结果如何，替换时都必须保留原数据库和封面，且不自动删除；不能保留旧库时中止，替换或最后处理封面失败时尝试回滚。

导入后的处理取决于文件是否替换成功，以及原数据库能否恢复：

| 结果 | 应用行为 |
| --- | --- |
| 新库导入成功 | 自动重启，重新建立连接并使用新库。 |
| 替换失败，原数据库已恢复 | 提示失败后重启，重新建立连接并继续使用原库。 |
| 替换失败，原数据库也无法恢复到正式路径 | 显示旧库保留位置，停止自动重启，需先关闭应用并人工恢复文件。正式路径可能缺少数据库，此时直接重启可能创建空库。 |

上述重启是为了重新建立已关闭的数据库连接；关闭连接前的校验失败或用户取消不需要重启。自动回滚仅在程序仍在运行、能够处理错误时执行；若替换过程中断电或进程被强制结束，下次启动不会自动恢复保留的旧文件。

## 存档备份与恢复

`backup/savedata/` 承担存档归档、创建、维护和恢复。创建、恢复、删除、历史清理及根目录迁移共用存档操作锁。

### 归档格式与恢复目标

新备份使用 `savedata_v2_` 前缀的 V2 归档，保留普通文件或目录的原名，且只能有一个逻辑顶层对象。其他文件按 Legacy V1 处理，版本由文件名判定；V1 是目录内容备份，恢复到当前配置的存档目录。

V2 按备份原名恢复完整对象，拒绝类型冲突和意外覆盖；实际恢复位置可与当前配置不同，返回位置但不自动改写游戏配置。名称比较与目标选择规则见 [`backup/savedata/restore`](../../src-tauri/src/backup/savedata/restore)。

恢复预检限制路径、条目类型和资源用量，拒绝链接、路径越界及会重定向路径的 reparse 对象。全部内容在目标同卷临时目录解压并验证后，通过 rename 整体替换，禁止目录合并。失败尝试回滚；回滚失败保留旧对象并报告位置。该恢复事务只处理运行时失败，没有断电后自动恢复。

### 文件与记录一致性

创建 command 在归档自检后登记数据库；写库失败补偿删除新归档，登记成功后才清理历史备份。删除文件失败或文件缺失时保留记录，仅在用户明确选择清除记录后单独删除；自动清理不能代替用户做此决定。

### 备份根目录切换

存档备份根目录必须通过专用迁移工作流切换，不能只更新设置；入口为 [`backup/savedata/maintenance.rs`](../../src-tauri/src/backup/savedata/maintenance.rs)。

存在历史备份时，复制并校验目标完整性后才能提交配置，再清理旧根目录；提交前失败保持原配置，提交后清理失败返回残留目录警告。目标必须经过冲突和完整性检查，不能覆盖无关文件。

迁移只清理明确不存在的失效记录，并与配置更新共同提交；权限和网络错误不能视为文件缺失。

## HTTP、更新与错误边界

`utils/http/client.rs` 管理普通请求和下载传输客户端。显式应用代理优先，留空时使用系统代理；Windows 监听系统代理变化并替换客户端，已有请求和运行中的安装任务继续使用旧客户端，后续请求及新启动、恢复的任务使用新客户端。

Windows 应用内更新以当前 EXE 所在目录为目标，维护安装登记或便携模式数据边界，便携更新保留 `resources`。修改入口为 `utils/updater.rs` 和 `src-tauri/windows/`。

Command 是文件系统和系统 API 的参数校验边界。多数 command 返回带中文上下文的 `Result<T, String>`，仓储保留 `DbErr`，安装失败提供稳定 `code`；前端 `BaseService` 统一转为 `AppError`。

本地游戏启动的路径校验失败通过启动结果中的可选 `path_issue` 提供问题类型与实际路径，前端据此引导重新选择并在保存后重试；其他启动失败不进入路径修正流程，不能通过匹配错误文案判断是否需要修正。
